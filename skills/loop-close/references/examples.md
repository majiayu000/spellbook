# 例子

## 新能力：把一个多步骤工作流接入 CLI 和 MCP

| 步 | 内容 |
|---|---|
| ① | 推动"客单"。假设：广告类用户能在 Agent 里直接跑广告工作流，每个付费账户的月消费会上升。护栏：失败率、退款率。失败判定：第 4 周没有付费账户用过第二次 |
| ② | 发现（已有）→ 输入（Schema 已有，缺上传引导）→ 报价（已有）→ 确认（已有阈值）→ 执行（要做专用入口）→ 进度（要做 wait）→ 交付 → 修改（不适用）→ 计费（核对和网站一致） |
| ③ | 新增 workflow_list / get / run，沿用共同契约 |
| ⑤ | 一个图片模板 + 一个视频模板，两个入口对测，和网站同输入比对；新 Agent 独立完成 |
| ⑧ | 第 2、4 周复盘：扩到其余模板、修，还是停 |

## 调研：某竞品的 MCP 设计值得借鉴吗

| 步 | 内容 |
|---|---|
| ① | 要支撑的决定：下季度要不要给自己的 MCP 加"预设执行"类工具。放弃条件：对方的这类工具实际调用很少，或我们的用户没有对应任务 |
| ② | 问题 → 收集实测证据和源码证据 → 和自己的现状对照 → 结论 |
| ③ | 证据分级：实测 / 源码 / 文档 / 推测 |
| ⑥ | 一页结论给决策人，不交几十页资料 |
| ⑧ | 写出"采用 / 否定 / 待验证"，交给知识库类 Skill 入库；下次同类问题先查这条 |
