# 任务链路清单

第 ② 步对着这张表过一遍，每格标"已有 / 要做 / 不适用"。**常见的半成品，是只做了"执行"这一格。**

## 通用版（产品功能、工具、Agent 能力）

| 环节 | 要回答的问题 |
|---|---|
| 发现 | 使用者（人或 Agent）怎么知道有这个能力、什么时候该用？ |
| 输入 | 需要什么？缺了怎么问？错误输入能不能在执行前拦住？ |
| 报价 | 花钱或花时间之前，能不能先知道大概多少？ |
| 确认 | 什么情况必须让人点头？ |
| 执行 | 返回什么？超时、重复提交怎么办？ |
| 进度 | 长任务怎么看进度？中断后能否接着等？ |
| 交付 | 结果在哪？能直接看、直接拿走吗？交付失败能单独重试吗？ |
| 修改 | 能不能只改一部分？ |
| 复用 | 下次能接着用这次的素材和结果吗？ |
| 计费 | 预估和实际分开吗？失败扣不扣？扣到正确的人吗？ |
| 反馈 | 发现问题怎么报上来？ |

## 换场景时的对应

| 事情 | ② 走通什么 | ③ 定什么规则 | ⑦ 看什么数 |
|---|---|---|---|
| 产品功能 | 用户从需求到成果再到修改 | 接口、计费、版本 | 采用率、留存、付费 |
| 增长活动 | 看到 → 点开 → 注册 → 首次成功 | 渠道归因口径 | 各渠道新注册与激活 |
| 调研 | 问题 → 证据 → 结论 | 证据分级 | 是否支撑出一个决定 |
| 文档、网站、演讲 | 打开 → 看懂 → 行动 | 统一术语与口径 | 读者能否据此做事 |
| 开源项目 | 发现 → 安装 → 跑通 | 接口与兼容规则 | 安装后成功率、留存、issue |
